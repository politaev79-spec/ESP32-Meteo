Путь проекта: C:\Users\User\Documents\ESP32_C3_BMP280

----------------------------------------
1. ЗАДАЧА
----------------------------------------
Сделать из ESP32-C3 Super Mini + датчика BMP280 локальную
метеостанцию:

1) Открытая WiFi-сеть (AP) «ESP32-Meteo» для доступа с телефона.
2) Web-интерфейс с живыми показаниями (обновление раз в 2 с):
   - температура (°C);
   - давление (мм рт. ст.);
   - высота (м) — барометрическая формула.
3) Собственный (нативный) драйвер BMP280 по I2C, БЕЗ внешних
   библиотек.
4) Опция параллельного подключения к домашней сети (AP+STA).
5) USB-лог через HWCDC (COM-порт), т.к. на C3 по умолчанию
   Serial = UART0 (GPIO20/21), а не USB.

Пины I2C: SDA=GPIO0, SCL=GPIO1 (перенесены с GPIO8/9, см. п.6).

5. ПРОБЛЕМЫ / ТЕКУЩИЙ СТАТУС  (РЕШЕНО, 2026-09-06)
----------------------------------------
ДАТЧИК РАБОТАЕТ. Были две проблемы: пины и баг в формуле давления.

- ШАГ 1 (пины): GPIO8/9 (LED + BOOT) давали НЕСТАБИЛЬНУЮ связь
  (то находит, то «w err»). Перешли на ЧИСТЫЕ пины GPIO0/1 — связь
  стабильная. (Сканы на 12 парах пинов.)
- ШАГ 2 (баг в bmp280.h): давление было в 256 раз завышено
  (P≈253482 гПа вместо ~1013). 64-битная формула Боша возвращает p
  в единицах 1/256 Па, а код возвращал p без деления на 256.
  ФИКС: `return (float)(p / 256.0);` — давление стало корректным.
- У модуля ТОЛЬКО BMP280 (0x76), AHT20 (0x38) НЕТ — это отдельный
  датчик давления, а не комбо AHT20+BMP280.
  Сделан запасной вариант: температура берётся из BMP280.
- ВЛАЖНОСТЬ УБРАНА (по просьбе). Пункт удалён из Web-UI, API и кода.
  Датчика влажности на плате нет (только BMP280).
- ДАВЛЕНИЕ: выводится в мм рт. ст. (1 мм рт. ст. = 133.322 Па).
  ФИКС в main.cpp: g_press / 133.322f в API, HTML-единица «мм рт. ст.».
- ДОБАВЛЕН ДАТЧИК DS18B20 (УЛИЦА): 1-Wire на GPIO4, подтяжка 4.7к.
  Голый чип TO-92 (не KY-001). Драйвер: OneWire + SKIP ROM + CRC
  (include/ds18b20.h). Сначала не читался — помогла перепайка +
  корректная подтяжка. Реализован «Улица»/«Дом».
- ПОДТВЕРЖДЕНО прошивкой (COM9):
  BMP280 OK at 0x76
  [OK] init BMP280 T=21.08 C P=743.41 mmHg Alt=185.8 m
  [OK] init DS18B20 out=21.88 C  — оба датчика работают!
  (Дом 21.1 °C, Улица 21.9 °C, Давление 743 мм рт. ст.)
- Web API: /api возвращает out(улица), temp(дом), press(мм рт. ст.), alt.
  В UI 4 карточки: Улица, Дом, Давление, Высота (влажности нет).

6. ВАЖНЫЕ ГРАБЛИ (уже пройдены — НЕ повторять)
----------------------------------------
- НЕ включать ARDUINO_USB_CDC_ON_BOOT=1 или ARDUINO_USB_MODE=1:
    * USB_MODE не поддерживается C3 (нет tinyusb) -> USB не объявляется.
    * CDC_ON_BOOT ломает сборку framework (Serial не объявлен).
- Serial по умолчанию на C3 = UART0 (GPIO20/21), НЕ на USB.
  Для USB-лога (COM-порт): определить свой `HWCDC usbLog;`
  (include <HWCDC.h>) и печатать в него. Это не ломает сборку.
- GPIO8 = синий LED, GPIO9 = strapping (BOOT). Для I2C лучше
  НЕ использовать (влияют на шину). Сменить пины -> менять и
  config.h, и физические провода.
- Скан I2C делать ОДНИМ чистым проходом (однократный Wire.begin +
  pullup), а не многократно переинициализировать Wire.
- Порядок диагностики пустой шины: питание модуля -> непрерывность
  SDA/SCL -> другие пины -> признать брак модуля.

----------------------------------------
7. СЛЕДУЮЩИЕ ШАГИ (когда принесут исправный модуль)
----------------------------------------
1. Подключить: SDA->GPIO0, SCL->GPIO1, VCC->3V3, GND->GND.
2. Проверить COM-порт (Get-CimInstance Win32_SerialPort).
3. pio run -t upload --upload-port COM<X>
4. Прочитать USB-лог: ожидать "BMP280 OK at 0x76/0x77", затем
   "[OK] T=.. C P=.. mmHg Alt=.. m".
5. Проверить Web UI: подключиться к «ESP32-Meteo», открыть
   http://192.168.4.1 (температура, давление, высота) — влажности нет.
